# Private source extension: staged ERP mechanism

This operator module extends an existing reference collection and changes the delivery identity of its previously mapped documents in one SQLite transaction. It is exercised with newly created synthetic databases. It has no HTTP route, CLI wrapper, browser UI, activation step, grant, download or publication action.

The API takes an authenticated Request, never an Actor DTO. planSourceExtension is query-only: it opens an existing explicit ERP path read-only and creates no schema or receipt. commitSourceExtension requires the exact reviewed plan SHA. Both require the exact persisted ADMIN session, tenant and owner, with checks after source IO, after the ERP write lock, after the writes and immediately before COMMIT. An aborted Request fails. Hooks are trusted in-process fault observers; transactional hooks are synchronous and cannot come from deserialized operator input.

The source locations are explicit private environment values: TAYCO_TAKEOFF_MANIFEST_PATH, TAYCO_TAKEOFF_RELATIONS_PATH and TAYCO_TAKEOFF_MAPPING_PATH describe the immutable parent; TAYCO_SOURCE_EXTENSION_BUNDLE_PATH and TAYCO_SOURCE_EXTENSION_RELATIONS_PATH describe the materialized candidate. TAYCO_ERP_DB_PATH and existing authentication configuration select the databases. There are no caller paths, fallback data roots, credentials in arguments, or global environment mutations.

The closed input binds parent and candidate bundle/relations identities and raw SHA pins, parent mapping SHA, existing destination project ID/context and exact project version. Existing bundle and relations schemas are reused. All old document and asset definitions must survive exactly as parsed; project metadata must survive with only document membership additions in the selected context. New PDF documents belong only to that existing reference collection. Reusing an old source SHA under a new ID is rejected. Mapping covers the complete old cohort without ambiguous document/project aliases. This is technical source eligibility; legacy document status "approved" does not approve quantities, prices, rights, recipients or commercial scope.

Both complete materialized bundles are verified against asset sizes and SHA with a 64 KiB read buffer. Metadata reads have fixed limits, each asset is limited to 512 MiB, each bundle to 2 GiB, with bounded catalog counts. Paths are confined, relative POSIX asset paths reject traversal and alternate delimiters, every path component is checked, and junctions/file hardlinks are denied. Before/after handle/path signatures catch observed replacement or alteration. After IO and before COMMIT, metadata is rehashed and asset signatures/configuration are rechecked. This is an observation of filesystem state, not an OS seal or a power-loss guarantee.

Plans bind every inherited document's version/raw payload SHA, all mapped projects and their exact row hashes, tenant/actor, raw source pins, new document payloads and proposed mapping. Old rows keep IDs, project, owner, source SHA/context and unrelated fields. An existing registeredSourceIdentity is preserved literally. A missing original identity is frozen from its old four delivery fields before updating delivery; no missing original contextKey is invented. Project rows are never created or changed. New document IDs use the existing registration identity algorithm.

The transaction uses BEGIN IMMEDIATE, compares the current plan again under lock, patches old delivery with version/payload CAS, inserts new documents, audit and one durable receipt. Any guard or SQL failure rolls back all ERP changes. It does not nest the legacy registration committer. A concurrent identical writer returns the same receipt/time with created/rebound zero. Replay re-verifies complete source bytes and exact committed rows/projects; changed state is rejected rather than repaired. A receipt result digest detects inconsistent stored result data. The immutable parent inputs must remain available for replay.

M02 receipts, binding tables, text overlays, quantities, finance and grants are outside this write set. Tests keep independent sentinel tables unchanged and preserve the two origin classes across a complete synthetic 42-old/6-new cohort.

## Activation boundary

A stored result is erp_staged_not_activated. This module does not change files, mapping, source DTO, processes, existing sessions or recipient policy. SQLite cannot atomically commit a mapping file and running viewer process. A separate reviewed activation block must provide the complete matching cohort and runtime guards before real use.

The new planner rejects parent-mapping/current-delivery mismatch. An exercised existing ADMIN viewerScope still resolves its old mapped documents after the synthetic ERP stage; it does not itself compare these delivery pins. The old IDs and source bytes are unchanged, and the additional document is not granted by that old mapping. Do not claim the production reader has a new cohort guard. Reader/gateway integration and its real runtime proof remain mandatory before activating a real transition.

No real source registration/rebinding, shared checkout integration, cloud release, recipient authorization or active-console change is certified by this isolated backend block.
