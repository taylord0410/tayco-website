# Consumer delivery cohort

The viewer binds current ERP delivery to the configured, hash-pinned v1 manifest and relations before projecting any authorized source. Bundle ID, manifest digest, relation ID and exact relation digest, current context, viewer document ID, source digest, kind and media must match. Missing delivery fields never become a legacy bypass. The existing role, tenant, project, document lifecycle and recipient-selection rules still determine the eligible subset. An unavailable or deleted document remains unavailable; this guard does not publish a whole catalog or establish an atomic switch of all company records.

The manifest is read through bounded, fatal UTF-8 policy IO and checked against the relation pin. Its identity projection, context/document membership and referenced assets are checked against relations. This reader does not rehash every physical asset, certify all producer metadata, seal files against later changes, or replace the materialized-bundle review. There is no new source format, grant, write endpoint or default configuration.

Generic guest queries read only explicit guard/delivery fields. Insurer scope intersects its immutable policy with the same current delivery checks. RegisteredSourceIdentity is retained as provenance: old origin pins cannot substitute for current delivery, and an original identity that lacked contextKey does not acquire one during a read.

The gateway repeats persisted-session authentication and scope checks before and after provider IO and stream reads. An in-flight response cannot switch relation bytes, even when the replacement metadata and ERP have coherently been repinned. Document JSON must also report the exact manifest-bound source digest. The document redirect rechecks the actor, row version and scope after its final await. Administrative profile links derive from that already guarded scope, without a second ERP snapshot that could join a different delivery cohort.

Existing synthetic fixtures now explicitly provide the manifest and current delivery they intend to authorize. Their permission, lifecycle, tenant, Range/HEAD and confidentiality assertions remain; no production fallback or automatic fixture repair is installed. The source-extension negative now expects old mapping to be withdrawn after staging; its pre-stage positive remains.

Verification uses actual production handlers with newly persisted synthetic accounts/requests for admin, staff, client, vendor, generic guest and insurer. Provider responses are controlled in-memory seams; this is not a cloud or live-user browser certification. Tests cover exact/changed/missing pins, source/context/media/kind mismatch, both original-identity classes, a fully coherent synthetic transition, provider-header and stream-read changes, revocation, tenant drift, actual redirects and profile-link projection. No real source, ERP, account, grant, active policy, browser tab or running user server is changed.
