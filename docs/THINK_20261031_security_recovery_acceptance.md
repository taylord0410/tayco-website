# Recovery must return to the same unfinished intention

The browser acceptance of Tayco B5 showed that server-owned counters are only half the recovery flow. A visitor needs visible primary actions, retained fields/reference IDs and a keyboard path through the notice. Closed details can still be returned by a naive selector; bounding the focus loop requires excluding their hidden descendants.

The actual loop returned: select reference → submit blocked → request review → authenticated manual resolution → check status → same unfinished form → explicit submit → durable receipt → admin sees the same reference. Recovery did not submit automatically and did not create an investigation grant. This is the useful distinction between abuse clearance and private authorization.

The dependency audit also required separate claims: production0 does not imply development0. Compatible scoped updates removed the high alert, while a callable CommonJS dependency prevented a global major override. The residual remains visible in ledger25701. A local acceptance can be concrete without inventing production/provider certification.
